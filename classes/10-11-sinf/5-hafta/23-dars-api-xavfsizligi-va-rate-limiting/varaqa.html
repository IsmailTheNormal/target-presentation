Laboratoriya Vazifasi: Token Bucket va HMAC Himoyasini Sinash

Node.js muhitida Token Bucket algoritmini ishga tushirish, 429 Too Many Requests javobini tekshirish, va HMAC-SHA256 so'rov imzolash orqali Replay Attack (takroriy so'rov) simulyatsiyasini qaytarish.

Xavfsizlik BosqichiDastur ParametrlariKutilgan NatijaHolat
1. Burst Sinovi`5 ta so'rov / 1 soniya`Barchasi muvaffaqiyatli: HTTP 200 OK✅ O'zlashtirildi
2. Cheklov (Rate Limit)`6- va 10-so'rovlar oralig'i`HTTP 429 Too Many Requests (Retry-After)
3. HMAC Imzo Tekshiruvi`X-Signature: sha256(canonical)`Imzo to'g'ri bo'lsa server qabul qiladi
4. Replay Attack Sinovi`Takroriy Nonce bilan so'rov`HTTP 401 Replay Attack Detected

Xavfsizlik Tahlili va Nazariy Savollar

1. Nega taqsimlangan mikroservislarda (Kubernetes klasterida) rate limiting lokal xotirada (RAM) emas, Redis orqali yuritilishi shart?


2. API so'rovlarida HMAC-SHA256 imzosi, X-Timestamp va X-Nonce birgalikda qanday qilib Replay Attack va Tampering hujumlarini to'xtatadi?

  • Laboratoriya bosqichlari to'liq bajarilgan va yozma savollarga asosli javob berilgan 2 ball
