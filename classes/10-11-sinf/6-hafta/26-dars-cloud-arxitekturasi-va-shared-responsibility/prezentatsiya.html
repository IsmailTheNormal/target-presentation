Cloud Arxitekturasi va Umumiy Mas'uliyat Modeli

Nega serverlarni AWS, GCP va Azure ga ko'chirish kiber-xurujlardan avtomatik himoya qilmaydi? IaaS vs PaaS vs SaaS arxitekturasi, bulut provayderi va mijoz o'rtasidagi mas'uliyat chegaralari hamda Tesla ning ochiq Kubernetes podi kiber-halokati tahlili.

Infratuzilma Evolyutsiyasi

Podvaldagi Serverlardan Giperskalerlargacha

🏢 An'anaviy On-Premises

  • Kompaniya jismoniy serverlar, kabellar, konditsionerlar va generatorlarni o'zi sotib oladi.
  • 100% mas'uliyat kompaniyada: qo'riqchidan tortib Linux operatsion tizimi xavfsizligigacha.
  • Juda sekin: yangi server sotib olish va sozlash bir necha hafta va oylab vaqt olardi.

☁️ Ommaviy Bulut (Cloud)

  • Infratuzilma API yoki Terraform orqali 10 soniyada dunyoning istalgan nuqtasida ko'tariladi.
  • Jismoniy xavfsizlik (biometriya, qo'riqlash) jahon darajasidagi provayderlar qo'lida.
  • YANGI XAVF: IAM yoki tarmoq konfiguratsiyasidagi bitta xato butun tizimni internetga ochib qo'yadi!
Bulutli Servis Modellari

IaaS vs PaaS vs SaaS: Qatlamlarni Kim Boshqaradi?

Tanlangan model jamoangiz aynan qaysi xavfsizlik qatlamlariga javobgar ekanini belgilaydi.

Texnologik Qatlam IaaS (AWS EC2, GCP Compute) PaaS (Vercel, AWS Lambda) SaaS (Google Workspace, Slack)
Ma'lumotlar va Auth Mijoz (Siz) Mijoz (Siz) Mijoz (Siz)
Ilova Kodi va API Mijoz (Siz) Mijoz (Siz) Provayder
OS, Patchlar, Runtime Mijoz (Siz) Provayder Provayder
Virtualizatsiya, Uskunalar Provayder Provayder Provayder
Bulutning Asosiy Qoidasi

Umumiy Mas'uliyat: "Security OF vs IN the Cloud"

🛡️ Security OF the Cloud (Provayder)

AWS va Google nimalarga kafolat beradi:

  • Ma'lumotlar markazlarining jismoniy qo'riqlanishi va biometrik kirish.
  • Uzluksiz elektr ta'minoti va sovutish tizimlari.
  • Virtualizatsiya va gipervizor (AWS Nitro) xavfsizligi.

⚔️ Security IN the Cloud (Mijoz — Siz)

Muhandis sifatida siz nimalarga javobgarsiz:

  • Ma'lumotlarni shifrlash (KMS kalitlari) va xavfsiz saqlash.
  • IAM siyosatlari: kim serverga va bazaga kirish huquqiga ega ekani.
  • Xavfsizlik guruhlari devori (Security Groups) va ochiq portlar.
Sanoat Haqiqati

"Bulut Xavfsizligi" Illyuziyasi va 99% Qoidasi

Gartner Kiberxavfsizlik Prognozi:
"2027-yilgacha bulutdagi xavfsizlik insidentlarining 99% provayder (AWS/GCP) zaifligi emas, balki MIJOZNING NOTO'G'RI SOZLAMALARI sababli sodir bo'ladi."

Xakerlar Amazon ma'lumot markazlarini buzib kirmaydi — ular muhandislar tomonidan ochiq qoldirilgan portlar va kalitlarni qidiradi.

Eng Katta 3 ta Xato Tushuncha

  • ❌ "Biz AWS damiz, demak avtomatik ISO/SOC2 talablariga javob beramiz" (Provayder faqat o'z binosini kafolatlaydi).
  • ❌ "Bulutdagi baza zaxira nusxaga (backup) muhtoj emas" (Xaker bazani o'chirsa, AWS uni tiklab bermaydi).
  • ❌ "Security Group o'zi himoya qiladi" (0.0.0.0/0 qoidasi barcha himoyani bekor qiladi).
Haqiqiy Kiber-Halokat

Tesla Keysi: Avtogigant Serverlarida Kripto-Xakerlik

🕵️ Hujum Qanday Sodir Bo'ldi?

  • Tesla muhandislari elektromobillar telemetriyasi uchun AWS da Kubernetes klasterini ko'tardi.
  • Kubernetes Dashboard boshqaruv paneli internetga PAROLSIZ ochiq qoldirildi!
  • Xakerlar panelga kirib, konteyner ichidagi ochiq AWS IAM maxfiy kalitlarini o'g'irladi.

💥 Oqibat va Muhandislik Sabog'i

  • Xakerlar Tesla hisobidan Monero qazib olish uchun yuzlab kuchli EC2 serverlarini yoqib yubordi.
  • Kripto-trafik xavfsizlik monitorlaridan yashirinish uchun Cloudflare orqali yo'naltirildi.
  • Xulosa: AWS infratuzilmasi buzilmadi. Bitta muhandisning parolsiz paneli barcha tizimni qulatdi.
Boshqaruv Arxitekturasi

Control Plane vs Data Plane: Hujumning Ikki Tekisligi

🎛️ Control Plane (API va Boshqaruv)

Bulut API interfeyslari va boshqaruv pulti:

  • Serverlar, ma'lumotlar bazalari va tarmoqlarni yaratish/o'chirish.
  • Himoya: Qat'iy MFA, IAM Least Privilege, AWS CloudTrail auditi.
  • Xaker egallasa: Butun kompaniya infratuzilmasi xaker qo'liga o'tadi!

📦 Data Plane (Trafik va Dasturlar)

Mijoz va server o'rtasidagi real ma'lumotlar oqimi:

  • HTTP/HTTPS so'rovlar, SQL tranzaksiyalari, fayl yuklashlar.
  • Himoya: AWS WAF devori, TLS 1.3 shifrlash, xususiy VPC tarmoqlari.
  • Xaker egallasa: Ilova orqali (SQLi/XSS) ma'lumotlar o'g'irlanadi.
Avtomatlashtirilgan Audit

CSPM va CIS Cloud Benchmark Standartlari

🔍 CSPM nima? (Cloud Security Posture)

Bulut konfiguratsiyasini kecha-yu kunduz avtomatik tekshirib turuvchi xavfsizlik skanerlari:

  • Internetga ochiq qolgan S3 xotira chelaklarini aniqlaydi.
  • 0.0.0.0/0 ga ochiq qolgan 22 (SSH) va 3389 (RDP) portlarini topadi.
  • Sanoat qurollari: Prowler (open-source), ScoutSuite, AWS Security Hub.

📋 CIS AWS Benchmark Standarti

  • 1.1-qoida: Root akkauntidan kundalik ishlar uchun foydalanish TAQIQLANADI.
  • 1.2-qoida: Barcha IAM foydalanuvchilariga majburiy 2FA/MFA o'rnatish.
  • 2.1-qoida: Barcha mintaqalarda AWS CloudTrail audit loglarini yoqish.
  • 3.1-qoida: Security Group da 22-portga 0.0.0.0/0 kirishini butunlay bloklash.
Muhandis Amaliyoti

Amaliy Ish: Bulut Arxitekturasi Xavfsizlik Auditi

Auditor Ssenariysi (Ishchi Varaqa)

Sizga fintex-startapning bulut infratuzilmasi taqdim etilgan. Shared Responsibility va CIS Benchmark bo'yicha 4 ta kritik xatoni toping:

  • RDS PostgreSQL bazasi ommaviy subnetda Public IP bilan joylashtirilgan.
  • Foydalanuvchilar pasporti saqlanuvchi S3 chelagi "Public Read" holatida.
  • Barcha mikroservislar bitta umumiy AdministratorAccess kaliti bilan ishlayapti.

Ikki Xil Bajarish Yo'li

💻 Noutbuk bilan:
IAM JSON siyosatini tahlil qilish va xavfsiz VPC subnet izolyatsiya qoidalarini tuzish.

📄 Noutbuksiz (qog'ozda):
IaaS/PaaS/SaaS mas'uliyat matritsasini to'ldirish va Tesla hujum zanjirini grafik chizish.

Xatolar Ovi

Bulut Muhandisining 5 ta Fatal Xatosi

⚠️ Xavfli Amallar

  • 1. IAM da `Action: *` berish — ilovalarga mutlaq cheksiz huquq ulashish.
  • 2. GitHub kodiga AWS kalitlarini yozib ketish (botlar uni 45 soniyada topadi).
  • 3. CI/CD deploy uchun Root AWS hisobidan foydalanish.

✅ To'g'ri Arxitektura

  • 1. Faqat kerakli resurs va amallargina ruxsat beruvchi Least Privilege.
  • 2. Statik kalitlar o'rniga vaqtinchalik IAM Rolllar (OIDC / Instance Profiles).
  • 3. Root akkaunt faqat favqulodda holatlar uchun YubiKey bilan qulflangan.
Dars Xulosasi

Bulut Xavfsizligining Oltin Qoidalari

1. Mas'uliyat Chegarasi

Provayder infratuzilmani qo'riqlaydi, ammo ichidagi ma'lumotlar, ruxsatlar va kodga faqat siz javobgarsiz.

2. Nol Public Baza

Hech qachon ma'lumotlar bazasini ochiq internetga (Public IP) chiqarmang. Faqat ichki xususiy tarmoq.

3. Doimiy Skaner

Infratuzilma doimiy tekshiruvda bo'lishi kerak. Har qanday xatolik CI/CD bosqichidayoq to'xtatiladi.

Mustaqil Topshiriq

Uy Vazifasi va 10 Ballik Baholash Mezoni

📋 Vazifa Mazmuni

  • 1. Ishchi varaqadagi IaaS, PaaS va SaaS mas'uliyat taqsimoti jadvalini to'ldiring.
  • 2. Tesla keysi bo'yicha tahlil yozing: klaster xakerligining oldini oluvchi 3 ta aniq xavfsizlik chorasi.
  • 3. Yangi startap loyihasi uchun 5 ta eng muhim CIS AWS Benchmark qoidasini shakllantiring.

🎯 Baholash Mezoni (10 Ball)

  • 3 ball: IaaS, PaaS va SaaS bo'yicha provayder va mijoz mas'uliyatini aniq ko'rsatish.
  • 4 ball: Tesla hodisasining chuqur texnik tahlili (IAM kalitlari oqishi va himoya chorasi).
  • 3 ball: CIS Benchmark bo'yicha amaliy va to'g'ri shakllantirilgan xavfsizlik qoidalari.
