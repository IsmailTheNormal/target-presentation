Bugun Debugging Nima?

Bug (Xato): dasturdagi kamchilik, kutilmagan to'xtalish.

Debugging (Отладка): xatolarni aniqlash, ularning ildizini topish va to'g'rilash jarayoni.

Professional dasturchi xatodan asabiylashmaydi — u konsolni ochib, kiber-detektiv kabi izlanadi.

Uch Asosiy Xato Turi

Uch Dushman: Syntax, Runtime va Logic Xatolari

1. Sintaksis Xatosi

Qoidalar buzilgan

Grammatik xato: yopilmagan qavs, qo'shtirnoq, sintaktik buzilish. Brauzer kodni hatto ishga tushirmay to'xtaydi.

let x = (10 + 5; // Qavs yo'q!

2. Ijro (Runtime) Xatosi

Ish jarayonida qulash

Sintaksis to'g'ri, dastur ishga tushadi, lekin ijro paytida qulaydi: `null` ustida amallar, mavjud bo'lmagan metodlar.

null.addEventListener();

Eng xavflisi!

Konsolda qizil xato YO'Q! Kod xatosiz ishlaydi, lekin natija noto'g'ri: ball qo'shilishi o'rniga o'chib ketadi, eshik ochilmaydi.

score = 10; // += o'rniga =

2-Toifa: Runtime Xatolari

TypeError: Cannot read properties of null — Dunyodagi Eng Ko'p Bug

Nega null yuzaga keladi?

HTML da bunday element yo'q yoki ID noto'g'ri yozilgan bo'lsa, `document.getElementById` elementi null (bo'shliq) qaytaradi.

Siz esa keyingi qatorda: `null.addEventListener(...)` deb buyruq berasiz. Brauzer hayron: 'Bo'shliqda hodisa datchigi bo'lishi mumkin emas!'

Selektorlarning Oltin Qoidasi

Metod Qanday yoziladi? Xato namunasi
getElementById 'myBtn' (panjarasiz!) ❌ '#myBtn'
querySelector '#myBtn' yoki '.card' ❌ 'myBtn'
💡 AI Debug Maslahati: Agar null chiqsa, HTML tegidagi id="" nomini nusxalab, JS dagi bilan solishtiring!
3-Toifa: Mantiqiy Xatolar

Mantiqiy Xatolar: Kod Yuguradi, Ammo Aldaydi

Nega Bu Eng Xavfli Xato?

Brauzer sizni ataylab shunday qildi deb o'ylaydi. Hech qanday ogohlantirish yo'q!

Sayt ochiladi, tugmalar bosiladi, ammo: do'konda narx arzonlash o'rniga qimmatlaydi, o'yinda dushmanga tegsangiz jon kamayish o'rniga ko'payib ketadi.

// 1. Tenglashtirish (=) va Solishtirish (===)
if (hp = 0) { // ❌ hp ni 0 qilib qo'yadi! }

// 2. Qiymatni yangilash

score += 10; // ✅ 10 qo'shib boradi
Brauzer DevTools

Asosiy Qurolimiz: DevTools va Console Oylasi

Konsolni Qanday Ochamiz?

Ixtiyoriy zamonaviy brauzerda:
• Klaviaturada F12 tugmasini bosing
• Yoki Ctrl + Shift + I (Mac: Cmd + Opt + I)
• Yoki sichqonchaning o'ng tugmasi → Inspect (Kodni tekshirish) → Console menyusi.

Console Buyruqlari

console.log("Oddiy xabar"); // Oq matn
console.warn("Diqqat: batareya kam!"); // Sariq ogohlantirish
console.error("Tizimda avariya!"); // Qizil xato
console.table(['Ali', 'Vali', 'Gani']); // Chiroyli jadval
💡 Kodning qayergacha yetib borganini bilish uchun har bir blok boshiga console.log('1-qadam bajarildi') qo'yib tekshiring!
Kiber-Detektivlik

Xatoni Qanday O'qiymiz? Stack Trace va Qator Raqami

Qizil Yozuvning 3 Qismi

1. Xato nomi: `TypeError` yoki `ReferenceError`.
2. Tushuntirish: `Cannot read properties of null`.
3. Manzil (O'ng burchakda): `script.js:42:15`.
Bu degani: script.js fayli, 42-qator, 15-belgi! O'sha havolani bossangiz, brauzer to'g'ridan-to'g'ri o'sha qatorni ochib ko'rsatadi.

Konsoldagi Ko'rinishi

Uncaught TypeError: btn is null
  at startGame (game.js:18:9)
  at HTMLButtonElement.dispatch (app.js:104:12)

Har doim eng yuqoridagi qatorga e'tibor bering: xato aynan o'sha funksiya ichida sodir bo'lgan!

Vaqtni To'xtatish

Breakpoints: Kodni Qadamma-qadam Ijro Etish

Nega Breakpoints Kerak?

O'nlab `console.log()` larni yozib o'tirmasdan, DevTools ning Sources bo'limida qator raqamini bosasiz.

Kod shu qatorga kelganda, brauzer vaqtni muzlatadi! Siz sichqonchani ixtiyoriy o'zgaruvchi ustiga olib borib, xotiradagi jonli qiymatni ko'ra olasiz.

Kod Ichida `debugger`

function calculateScore(points) {
  debugger; // DevTools shu yerda to'xtaydi!
  let total = points * 1.5;
  return total;
}

F10 tugmasi keyingi qatorga o'tkazadi, F8 esa dasturni davom ettiradi.
