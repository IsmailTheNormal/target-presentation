UY VAZIFASI TAHLILI VA O'TGAN DARS KO'PRIGI

29-Dars Tahlili: Asinxron JS va HTTP Polling Qopqoni

29-darsda Promise va async/await asinxronligini o'rgandik. Keng tarqalgan xato — har soniyada `setInterval(fetch, 1000)` bilan serverdan xabar so'rash nega halokatga olib kelishini ko'ramiz:

Keng Tarqalgan Xato (HTTP Polling)

Cheksiz HTTP So'rovlar Bo'roni

// ❌ XATO: Har 1 soniyada serverga so'rov urish!
setInterval(async () => {
  const res = await fetch("/api/messages");
  const data = await res.json(); // 99% holatda bo'sh []!
}, 1000);

1000 ta foydalanuvchi soatiga 3 600 000 ta HTTP so'rov hosil qiladi. 99% so'rovlar bo'sh qaytib, serverni qotiradi.

Oltin Yechim (WebSockets)

Doimiy Ochiq TCP Tunnel

// ✅ TOZA STANDART: Doimiy ochiq soket!
const socket = new WebSocket("ws://192.168.1.50:8080");

// Server o'zi yangi xabar kelganda itarib beradi (Push)
socket.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  displayMessage(msg);
};

Hech qanday keraksiz so'rov yo'q! Ulanish 1 marta ochiladi. Kechikish 1 soniyadan 5 millisekundga tushadi!

YANGI PARADIGMA · OCHIQ TCP TUNNELI

WebSockets: 101 Handshake Orqali Doimiy Full-Duplex Tunnel

WebSocket odatiy HTTP so'rovi kabi boshlanadi, lekin ulanish yopilmasdan, server bilan doimiy ochiq tunnelga aylanadi:

Handshake Qadamlari

  • 1. Client so'rovi: `Upgrade: websocket` va maxfiy `Sec-WebSocket-Key` jo'natadi.
  • 2. Server javobi: `HTTP/1.1 101 Switching Protocols` bilan rozi bo'ladi.
  • 3. Tunnel ochildi: Endi ulanish hech qachon yopilmaydi (Full-Duplex).
  • 4. Jonli Push: Ikkala tomon ham istalgan soniyada bir-biriga xabar bera oladi!
Tezlik Taqqoslashi
HTTP Polling: ~1200 ms vs WS: ~4 ms

WebSockets har bir xabar uchun yangitdan TCP/TLS ochmaydi. Xabarlar atigi 2 baytlik engil freymlarda oqib o'tadi!

KIBER-DETEKTIVLIK · TARMOQ FREYMLARI

WebSocket Freymlari: Opcodes va Chrome DevTools Tahlili

Chrome DevTools -> Network -> WS bo'limida har bir o'tgan paketni jonli ushlab ko'rish mumkin. Har bir freym o'zining maxsus Opcode turiga ega:

Asosiy Opcodes Turlari

Opcode Turi Maqsadi
0x1 Text (UTF-8) JSON matnlari va xabarlar
0x2 Binary Ovoz, rasm, fayllar
0x8 Connection Close Ulanishni xavfsiz yopish
0x9 Ping Aloqa tirikligini tekshirish
0xA Pong Pingga javob (Latency hisobi)

BACKEND VA TARMOQNI BOSHQARISH

WebSocket Server Qanday Ishlaydi: Broadcast Tarqatish Tsikli

Server unga ulangan barcha kompyuterlarning soketlarini xotirada saqlaydi. Bitta o'quvchi xabar yozganda, server uni hamma o'quvchilarga tarqatadi (Broadcast):

Node.js Server Kodi 
const { WebSocketServer, WebSocket } = require('ws');
const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (socket) => {
  console.log('⚡ Yangi o\'quvchi ulandi!');

  socket.on('message', (raw) => {
    // 1. Kelgan xabarni hammaga tarqatish (Broadcast)
    wss.clients.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(raw.toString());
      }
    });
  });
});

Serverning 3 Ta Oltin Qoidasi

  1. readyState Tekshiruvi: Faqat client.readyState === WebSocket.OPEN bo'lgan soketlarga yoziladi!
  2. Xonalarni Ajratish: #red-team xabarlari #blue-team o'quvchilariga bormasligi kerak.
  3. Tozalash: Darchani yopgan o'quvchi xotiradan o'chirilishi shart.
BRAUZERDA JONLI ULONISH

Klient Hayot Tsikli: onopen, onmessage va Avto-Qayta Ulanish

Brauzerda hech qanday tashqi kutubxonasiz ishlovchi rasmiy WebSocket API mavjud. U 4 ta asosiy hodisaga ega:

Vanilla JS Klient 
const ws = new WebSocket("ws://192.168.1.50:8080");

ws.onopen = () => {
  console.log("🟢 Serverga ulandik!");
  ws.send(JSON.stringify({ type: "JOIN", user: "Ali" }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log("📩 Yangi xabar:", data);
};

ws.onclose = () => {
  console.warn("🔴 Aloqa uzildi! Qayta ulanish...");
  setTimeout(connect, 3000); // Auto-reconnect
};
