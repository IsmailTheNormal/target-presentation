FRONTEND VA KIRUVCHI MA'LUMOTLAR

XSS Himoyasi: Zaifliksiz toza DOM render qilish

Eng katta xato — serverdan kelgan matnni to'g'ridan-to'g'ri innerHTML ga berishdir. Xaker kiritgan bitta script tegi foydalanuvchi cookie-parolini o'g'irlab ketadi. 

// XAVFLI KOD:
userDiv.innerHTML = response.userName; // XSS xavfi!

// XAVFSIZ VA PROFESSIONAL KOD:
userDiv.textContent = response.userName; // 100% xavfsiz matn
// Yoki boy HTML kerak bo'lsa:
userDiv.innerHTML = DOMPurify.sanitize(response.userBio);
  • 01 textContent qoidasi: Brauzer matnni kod deb emas, shunchaki inert harflar sifatida xavfsiz chizadi.
  • 02 DOMPurify filtri: HTML ichidagi barcha zararli script, onerror va onload tuzoqlarini kesib tashlaydi.

FULL-STACK ISHONCH PERIMETRI

Himoyalangan veb-servisning to'liq arxitekturasi

Barcha qatlamlar izolyatsiya qilingan: buzg'unchi SQLi yoki XSS jo'natgan taqdirda ham, middleware va parametrlash uni chegaradayoq yo'q qiladi.

SQL INJECTION GA QARSHI 100% QALQON

Parametrlangan so'rovlar: SQL Injection ga chek qo'yish

SQL qatorlarini matn sifatida birlashtirish (`'WHERE id = ' + req.body.id`) — xakerga butun bazani bitta tirnoq (') bilan o'chirish imkonini beradi. 

// ZAIF VA XAVFLI:
db.all(`SELECT * FROM users WHERE email = '${email}'`); // SQLi!

// XAVFSIZ VA PARAMETRLANGAN:
db.all(`SELECT * FROM users WHERE email = ?`, [email], (err, rows) => {
  // Ma'lumotlar buyruq deb emas, sof parametr sifatida uzatiladi
});
  • 01 Placeholder «?» belgisi: Ma'lumotlar bazasi avval so'rov tuzilmasini kompilyatsiya qiladi, so'ngra qiymatni passiv ma'lumot deb qabul qiladi.
  • 02 Foreign Key yaxlitligi: Buyurtmalar mavjud bo'lmagan foydalanuvchiga tegishli bo'lib qolmasligi uchun tashqi kalitlar majburiy tekshiriladi.

JWT VA XAVFSIZ COOKIE SIKLI

HttpOnly va SameSite: Kirish tokenlarini o'g'rilikdan asrash

Agar foydalanuvchi tokeni localStorage da saqlansa, har qanday XSS buzg'unchisi uni bitta buyruq bilan o'g'irlab ketishi mumkin. 

// XAVFSIZ AUTH COOKIE O'RNATISH (Express):
res.cookie('token', jwtToken, {
  httpOnly: true, // JavaScript o'qiy olmaydi (XSS dan 100% himoya!)
  secure: true,   // Faqat shifrlangan HTTPS orqali yuboriladi
  sameSite: 'strict', // Tashqi soxta so'rovlardan (CSRF) to'liq himoya
  maxAge: 3600000 // 1 soatlik amal qilish muddati
});
  • 01 HttpOnly bayrog'i: JavaScript ga cookie fayllarini o'qishni butkul taqiqlaydi va XSS o'g'irliklarini nolga tushiradi.
  • 02 SameSite=Strict: Begona soxta saytlardan jo'natilgan so'rovlarga token qo'shib yuborilishini to'xtatadi.
JONLI KIBER-TEST VA YECHIM (FIX)

Kiber-Sinov: Quyidagi kodda qaysi kritik zaiflik bor?

Quyidagi Express server kodini tekshiring va to'g'ri tashxisni belgilang: 

app.post('/api/profile', (req, res) => {
  const query = "UPDATE users SET bio = '" + req.body.bio + "' WHERE id = " + req.user.id;
  db.run(query);
  res.send("<h1>Updated:</h1><div>" + req.body.bio + "</div>");
});
A Kod xavfsiz, chunki GET o'rniga POST ishlatilgan.
B Kritik zaiflik: bir vaqtning o'zida ham SQL Injection, ham XSS mavjud!
C Yagona muammo faqat Content-Type sarlavhasi yo'qligida.
// MUHANDISLIK TUZATMASI (FIX):
// 1. SQLi ni tuzatish: db.run("UPDATE users SET bio = ? WHERE id = ?", [req.body.bio, req.user.id]);
