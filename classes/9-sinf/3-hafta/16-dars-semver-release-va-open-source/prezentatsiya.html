✅ Korporativ standart: SemVer 2.0.0:
  • Yagona xalqaro 3 raqamli triada: MAJOR . MINOR . PATCH.
  • Har bir raqam qat'iy texnik va me'moriy kafolat beradi.
  • Paket menejerlari (npm, pip) nimalarni avtomatik yangilash xavfsizligini biladi.
SemVer 2.0.0 Anatomiyasi

Open Source Olamini Boshqaruvchi 3 Raqam

MAJOR
v 2 . 0 . 0

Buzuvchi o'zgarishlar (Breaking change)! Eski kod ishlamaydi. Yangitdan yozish shart.

MINOR
v 1 . 5 . 0

Yangi imkoniyatlar qo'shildi. Eski kodlar buzilmay, bekamu-ko'st ishlayveradi (orqaga mos).

PATCH
v 1 . 4 . 8

Xatolar va xavfsizlik kamchiliklari tuzatildi. API o'zgarmagan, yangi funksiya yo'q.

⚠️ Havaskorlarning eng katta xatosi:

SemVer o'nli kasr emas! `1.9.0` dan keyingi yangi imkoniyat versiyasi `1.10.0` bo'ladi (`2.0.0` emas!). `2.0.0` faqat eski kod bilan nomuvofiqlik (breaking change) yuz bergandagina qo'yiladi.

Buzuvchi O'zgarishlar

Dasturchi Qachon MAJOR Raqamni Oshirishi Shart?

1-misol: Funksiya imzosi va parametrlarining o'zgarishi
// v1.4.0 (Eski versiya): function login(user, password) { ... } // v2.0.0 (Yangi breaking change): // Endi obyekt va token talab qilinadi! function login({ email, password, mfaToken }) { ... }

Eski chaqiruvlar `undefined` yoki xato beradi. Bu 100% Breaking Change!

2-misol: Eski metodlarni butunlay o'chirib tashlash
// v1.x da ogohlantirish berilgan edi: deprecated: 'Use api.request() instead' // v2.0.0 da metod butunlay yo'q: // window.CyberApp.oldMethod() -> Uncaught TypeError!

Katta kompaniyalar MAJOR chiqarmasdan avval oylar davomida ogohlantirish beradi.

Paket Boshqaruvi

Package.json Sirlari: Caret (^) va Tilde (~)

Caret (^) — zamonaviy standart ^1.2.3

MINOR va PATCH yangilanishlarini avtomatik qabul qiladi, lekin MAJOR ga ruxsat bermaydi.

"^1.2.3" qabul qiladi: 1.2.4, 1.3.0, 1.9.9 "^1.2.3" BLOKLAYDI: 2.0.0 (Xavfli!)
Tilde (~) — ultra-konservativ ~1.2.3

Faqat PATCH (xato tuzatish)ni qabul qiladi. Hatto MINOR yangi imkoniyatlarni ham rad etadi.

"~1.2.3" qabul qiladi: 1.2.4, 1.2.9 "~1.2.3" BLOKLAYDI: 1.3.0 va 2.0.0
Git Tags

Git Tags: Tarixga Toshga O'yilgan Belgilar

Branch va Tag o'rtasidagi farq nima?
  • Branch (Tarmoq): Harakatlanuvchi ko'rsatkich. Har yangi kommit bilan oldinga siljiydi.
  • Tag (Yorliq): Toshga o'yilgan doimiy kommit. Hech qachon o'zgarmaydi va siljimaydi!
Git Tag yaratish buyruqlari:
# 1. Izohli (annotated) teg yaratish: git tag -a v1.0.0 -m "Production Release 1.0.0" # 2. Teglarni ko'rish: git tag -l # 3. Masofaviy serverga (GitHub) yuborish: git push origin v1.0.0
GitHub Releases

Rasmiy GitHub Release va Professional CHANGELOG

GitHub Release sahifasi qanday elementlardan iborat?
  • Tag ref: Muzlatilgan Git tegi (masalan: v1.0.0).
  • Release Notes: Yangiliklar, tuzatilgan xatolar, mualliflar ro'yxati.
  • Assets: Avtomatik Source code.zip va tayyor fayllar.
"Keep a Changelog" xalqaro standarti:
## [1.0.0] - 2026-09-24 ### Added - Jonli valyuta konverteri va qorong'i rejim ### Fixed - iOS Safari brauzerida overflow xatoligi tuzatildi ### Security - API kalitlari .env fayliga ko'chirildi
Litsenziyalar

Ochiq Manba Litsenziyalari: MIT, Apache 2.0 va GPL v3

Litsenziya Tijoriy foydalanish Patent himoyasi Copyleft (Kodni ochish sharti)
MIT ✅ Ruxsat berilgan ❌ Maxsus shart yo'q ❌ Kodni yopib, tijoriy sotish mumkin
Apache 2.0 ✅ Ruxsat berilgan ✅ Kuchli patent kafolati ❌ Kodni yopish mumkin (Google, Kubernetes)
GPL v3 ✅ Ruxsat berilgan ✅ Patent himoyasi bor ⚠️ Majburiy ochiq kod! (Linux, Blender, Git)
💡 Agar GitHub repoda `LICENSE` fayli bo'lmasa — bu kod qonunan ochiq emas ("All rights reserved"). Boshqalar undan foydalanishga haqli emas!
