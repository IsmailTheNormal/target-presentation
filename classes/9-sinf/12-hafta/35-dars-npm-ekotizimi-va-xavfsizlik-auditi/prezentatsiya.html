34-DARS UY VAZIFASI TAHLILI

34-dars Tahlili: Faqat Client-Side Validatsiya va ReDoS

Keng Tarqalgan Xato (Pitfall)

Faqat Brauzerda Tekshirish

Formadagi qizil hoshiya hech narsani anglatmaydi: hujumchi curl orqali so'rov yuborib, butun client tekshiruvini chetlab o'tadi. Ustiga greedy regex ReDoS keltirib chiqarishi mumkin.

// XATO: faqat frontendda tekshirish if (!email.includes('@')) return;
Oltin Standart (Best Practice)

Server + Ankralangan Regex

Serverda tekshiramiz, ^...$ ishlatamiz va uzunlikni cheklaymiz. Client tekshiruvi faqat qulaylik uchun.

// TO'G'RI: server-side + anchor const EMAIL = /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/; if (!EMAIL.test(email) || email.length > 254) reject();
Blitz Savol

Nega ^ va $ ankorlarisiz regex boshida yoki oxirida axlat bo'lgan satrni o'tkazib yuboradi?

Bugungi Mavzuga Ko'prik

Formani himoya qildik. Ammo zararli kod foydalanuvchidan emas, o'zimiz o'rnatgan paketdan kelsa-chi?

PACKAGE.JSON VA PACKAGE-LOCK.JSON

Hammasini Hal Qiladigan Ikki Fayl

Niyat

package.json

Nimani xohlayotganingizni yozadi: loyiha nomi, skriptlar va bog'liqlik versiya diapazonlari.

{ "scripts": { "test": "jest" }, "dependencies": { "express": "^4.19.2" } }
Fakt

package-lock.json

Aslida nima o'rnatilganini qotiradi: aniq versiyalar, bog'liqlik daraxti va sha512 yaxlitlik xeshlari.

"express": { "version": "4.19.2", "integrity": "sha512-..." }

💡 Lockfile Git'ga majburiy qo'shiladi. Usiz hamkasb va serverda turli versiyalar o'rnatiladi — «menda ishlayapti» xatosi odatiy holga aylanadi.

SEMANTIK VERSIYALASH · ^ VA ~

Bitta ^ Loyihani Jimgina Yangilashi Mumkin

Aniq

1.2.3

Aynan 1.2.3 o'rnatiladi. Maksimal bashoratlilik, lekin xavfsizlik yamoqlari avtomatik kelmaydi.

Patch

~1.2.3

Faqat patslarga ruxsat: 1.2.4, 1.2.9. Major va minor qulflangan.

Minor

^1.2.3

Minor yangilanishlarga ruxsat: 1.3.0, 1.9.9. Yangi funksiyalar moslikni buzishi mumkin.

left-pad keysi (2016):

Muallif 11 qator kodni reyestrdan o'chirdi — va dunyo bo'ylab minglab loyihalar bir kechada yig'ilmay qoldi. Boshqa birovning kodiga bog'liq bo'lish — real xavf.

DEPENDENCIES VA DEVDEPENDENCIES

Test Paketlarini Produksiyaga Olib Bormang

dependencies

Ilova ishlashi uchun kerak: express, pg, jsonwebtoken. Ular serverga boradi.

"dependencies": { "express": "^4.19.2", "pg": "^8.11.0" }

devDependencies

Faqat build va testlar uchun: jest, eslint, nodemon. Produksiyada kerak emas.

"devDependencies": { "jest": "^29.7.0", "eslint": "^8.57.0" }
Server uchun buyruq:

npm ci --omit=dev faqat runtime bog'liqliklarini lockfile bo'yicha o'rnatadi. Kamroq paket — kichikroq hujum yuzasi.

TYPO SQUATTING · POSTINSTALL

Ta'minot Zanjiriga Hujumlar Qanday Ko'rinadi

Hujum 1

Typosquatting

Hujumchi nomida xatoli paket chop etadi: cross-env o'rniga crossenv. Siz uni original deb o'rnatasiz.

# XATO: nomni tekshirmaslik npm install crossenv
Hujum 2

postinstall Skripti

Paket o'rnatilganda o'z skriptini ishga tushiradi: .env ni o'qiydi va tokenlarni hujumchi serveriga yuboradi.

"scripts": { "postinstall": "node ./collect.js" }
Himoya:

Paket nomi, yuklab olishlar soni va repozitoriyni tekshiring. Skriptlar kerak bo'lmasa, --ignore-scripts bilan o'rnating. Commit oldidan lockfile diffini o'qing.

NPM AUDIT · DIAGNOSTIKA

npm audit: Zaifliklarni 10 Soniyada Topish

Uch Buyruq

npm audit # severity jadvali npm audit --json # mashina o'qiydigan npm audit fix # xavfsiz patch

npm audit fix --force major versiyani o'rnatib, loyihani buzishi mumkin. Avval hisobotni o'qing.

Severity Darajalari

  • 🔴 critical — darhol yamoqlash, relizni bloklaydi.
  • 🟠 high — produksiyadan oldin tuzatish.
  • 🟡 moderate — sprintga rejalashtirish.
  • ⚪ low — xavfni ongli qabul qilish.
LOCKFILE VA CI · TAKRORLANUVCHANLIK

npm ci: Har Qanday Mashinada Bir Xil O'rnatish

npm install va npm ci

npm install lockfile'ni yangilashi va boshqa versiyalarni o'rnatishi mumkin. npm ci node_modules'ni o'chirib, qat'iy lockfile bo'yicha o'rnatadi — CI uchun ideal.

npm ci --omit=dev npm audit --audit-level=high

GitHub Actions

- uses: actions/setup-node@v4 with: { node-version: 20 } - run: npm ci - run: npm audit --audit-level=high - run: npm test

Agar audit high/critical topsa, build yiqiladi (exit code 1) va yomon kod prodga tushmaydi.
