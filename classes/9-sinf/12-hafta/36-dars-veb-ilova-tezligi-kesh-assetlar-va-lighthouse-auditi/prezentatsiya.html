GOOGLE STANDARTI · CORE WEB VITALS

Sayt Tezligining 3 Ustuni: LCP, INP va CLS

Google har bir veb-ilovani 3 ta qat'iy metrika bo'yicha baholaydi. Agar ular qizil zonada bo'lsa, sayt qidiruvda pastga tushadi.

LCP · ≤ 2.5s

Eng Katta Kontent Yuklanishi

Ekrandagi eng yirik element (Hero rasm yoki asosiy sarlavha) to'liq ko'ringuncha ketadigan vaqt.

Yaxshi: < 2.5s | Yomon: > 4.0s
INP · ≤ 200ms

Klickga Javob Tezligi

Foydalanuvchi tugmani bosganidan ekranda javob chiqquncha o'tadigan vaqt. Og'ir JS ekranni qotiradi!

Yaxshi: < 200ms | Yomon: > 500ms
CLS · ≤ 0.1

Maketning Sakrashi (CLS)

«Sakrash effekti»: rasm kech yuklanib, foydalanuvchi bosmoqchi bo'lgan tugmani pastga surib yuborishi.

Yaxshi: < 0.1 | Ideal: 0.00
ASSETLAR OPTIMIZATSIYASI · RASMLAR

PNG (4 MB) vs WebP/AVIF (120 KB) va CLS Himoyasi

Zamonaviy Formatlar
  • JPEG / PNG (Eski): Telefon kamerasidagi rasm 4.2 MB bo'ladi. Mobil 3G tarmoqda 11 soniyada ochiladi.
  • WebP (Google): Xuddi o'sha sifatni saqlagan holda 30–75% yengilroq. Barcha brauzerlar qo'llab-quvvatlaydi.
  • AVIF: Eng kuchli siqish — trafikni 90% gacha tejaydi (4.2 MB ➔ 110 KB).
  • loading='lazy': Sahifa pastidagi rasmlarni faqat foydalanuvchi skroll qilganda yuklaydi.
Sakrashga Qarshi Kod (CLS = 0)

Har doim img tegiga width va height bering! Brauzer rasm yuklanishidan oldin joy ajratib qo'yadi.

<!-- ❌ XATO: CLS = 0.42 (Matn sakrab ketadi!) --> <img src="hero-4mb.png" /> <!-- ✅ TO'G'RI: LCP tez va CLS = 0.00 --> <img src="hero.avif" width="1200" height="630" loading="lazy" decoding="async" alt="Target Startup Hero" />
KRITIK YO'L · JAVASCRIPT YUKLANISHI

Ekranni Qotiruvchi Skriptlar: async vs defer

Brauzer <head> ichida oddiy <script> ko'rsa, HTML chizishni butunlay to'xtatib, oq ekranni ushlab turadi!

1. Oddiy <script>

HTML To'xtaydi ❌

HTML kutib turadi. Foydalanuvchi 3–5 soniya bo'm-bo'sh oq ekranga qarab o'tiradi.

2. <script async>

Parallel (Tartibsiz) ⚡

Fonda yuklanadi, tayyor bo'lishi bilan ishga tushadi. Faqat mustaqil analitika skriptlari uchun.

3. <script defer>

Oltin Standart ✅

Fonda yuklanadi va faqat HTML to'liq chizib bo'lingandan keyin tartib bilan ishga tushadi!

TARMOQDA SIQISH · GZIP VA BROTLI

Trafikni Yo'lda Siqish: Gzip vs Brotli

Nega matnli fayllarni siqamiz?

Kodlarda minglab takrorlanuvchi so'zlar bor. Server faylni zip qilib jo'natadi, brauzer esa millisekundda ochib oladi.

  • Gzip: Klassik standart, 1 MB JS kodni ~300 KB gacha siqadi (70% tejash).
  • Brotli (br): Google algoritmi, Gzip dan 20% kuchliroq (1 MB ➔ ~210 KB).
DevTools dagi HTTP Sarlavhalar
// Brauzer so'rovi (Request): Accept-Encoding: gzip, deflate, br, zstd // Server javobi (Response): Content-Encoding: br Content-Length: 21400 // (Asl hajmi 105 KB edi!)

Vercel, Cloudflare va zamonaviy Nginx serverlari HTTPS da Brotli ni avtomatik yoqadi.

BRAUZER KESHI · CACHE-CONTROL

Eng Tez So'rov — Umuman Yuborilmagan So'rov

Abadiy Kesh + Content Hashing

Agar CSS/JS o'zgarmasa, brauzer uni har safar yuklamasligi kerak. Fayl nomiga xesh qo'shib (app.a8f3e.js), keshni 1 yilga qulflaymiz!

// Statik assetlar (app.a8f3e.js, logo.webp): Cache-Control: public, max-age=31536000, immutable // Asosiy index.html (doim yangilanishi shart!): Cache-Control: no-cache // ETag orqali tekshiriladi
